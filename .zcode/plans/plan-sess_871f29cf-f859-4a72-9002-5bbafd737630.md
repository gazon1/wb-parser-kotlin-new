## Что осталось

> Раздел приведён в факт 2026-10-21 и обновлён 2026-10-22: проценты ниже — из
> merged-отчёта `koverXmlReport` (`LINE`, все модули вместе: 92,4 %), а не из прежней
> прикидки. Прежние числа («6 %», «14 %», «21 %») описывали состояние до серии PR #188–#214
> и давно неверны.

### 1. ~~`RealAdsPowerApi` — 6 %~~ — закрыто: 93,0 %

HTTP-клиент к Local API AdsPower покрыт: `RealAdsPowerApi` — 356 покрытых строк из 383
(93,0 %). Решения, которые он принимает, вынесены за шов и проверены тестами.

### 2. ~~Браузерный путь fetch — `BrowserDownloader` 14 %~~ — закрыто: 98,4 %

`BrowserDownloader` — 299 покрытых строк из 304 (98,4 %). Заодно закрыта и вторая часть
пункта («ошибка выглядит как “каталог вернул 0 товаров”»): разбор ответа, который не
подходит под модель, — это отказ с причиной (PR #191, #192), а не пустая страница; отказ
при этом сохраняет прочитанное (PR #213).

### 3. `PlaywrightCdpSession` / `PlaywrightCdpConnector` — 0 %

Остались два класса: 55 и 25 строк, обе без покрытия. Это тонкие адаптеры над
Playwright — «создать инстанс, подключиться по CDP, открыть страницу». Решения, которые
за ними стоят, покрыты через шов `CdpSession`/`CdpConnector` (поэтому `CdpAutomation` —
98,7 %, 150 строк из 152). Покрытие самих адаптеров требует настоящего Chrome: это
единственный класс тестов в репозитории, которому нужен браузер, а не сокет. Дыра
записана решением `2026-10-22-the-gaps-are-closed-or-written-down`.

### 4. Админский API — `AdminRoutes` 8,8 %

113 строк, 10 покрыты: маршрут `/api/admin/target-runs` закрыт (тест на настоящей базе),
а `/api/admin/targets`, `/api/admin/jobs` и `/api/admin/errors` — нет. Они читают базу и
отдают DTO, поэтому тест на них — это тест на запрос к базе, а не на логику.

### 5. Гейт покрытия измерял не те классы

Исправлено 2026-10-20: строки floors меряются по merged-отчёту с фильтром по пакетам.
До этого отчёт модуля `app` показывал 35 классов как непокрытые (0 %), хотя merged-отчёт
показывал 57–100 %: тесты этих классов живут в модуле `tests`, а отчёт модуля их не видит.
Floor `app` поднят с 31 % до 84 %. Сейчас: `wbparser` 93,5 %, `app` 90,1 %, merged 92,4 %;
полы подняты до 92 / 89 / 91 (по одному процентному пункту запаса).
