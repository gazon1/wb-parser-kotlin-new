# Стандарты кода / Coding standards

**Этот файл читает ревьюер, а не тот, кто пишет код.** Правила, которые может
проверить машина, живут в проверках сборки и видны тому, кто пишет код, сразу:
`scripts/ci/check-repo-rules.py` (механические правила ниже) и остальные гейты из
`scripts/ci/static-gates.sh`. Правила, которые машина решить не может, — здесь, и
их вводит ревью.

Правило, которое живёт только в документе, соблюдается тем, кто документ прочитал,
и никем больше. Поэтому всё, что можно выразить шаблоном, вынесено в проверку, а
здесь осталось то, что требует суждения: что именно является ошибкой в этом коде,
а что — допустимым решением.

**Always** добавляй сюда правило, когда оно не выразимо шаблоном, и **Never** не
дублируй здесь то, что уже проверяет сборка: дубликат устаревает тихо и стоит
контекста на каждом ходе.

---

## Ошибки не проглатываются

1. **Ошибка, пойманная в `catch`, обязана куда-то попасть.** Либо в `StageFailure`
   (стадия провалилась), либо в лог через `LogInterpreter`. `runCatching` без
   обработки — это не обработка: результат выбрасывается, и вызывающий код узнаёт
   об ошибке только по тому, что данных нет.

2. **`Side.Log(ERROR)` не игнорируется.** В save-стадии ветка `else -> {}`
   проглатывает ошибку молча, и crawl выглядит успешным, пока предметы не доехали.

3. **Ресурс освобождается на каждом пути.** Permit, соединение, файл — всё, что
   берётся перед работой, возвращается и когда работа провалилась. Утеря permit'а
   на пути отказа выглядит как «профиль исчез», а причина — в одной строке в
   `catch`, который никто не прочитал.

4. **Ошибка одного профиля не роняет весь краул.** DB, HTTP и внешние ресурсы
   идут через retry-loop (PR 11, G10). Транзиентный DB-блип не должен убивать
   прогон.

## Слои и границы

5. **Публичный тип модуля не называет тип, который модуль скрывает.** Модуль,
   который прячет библиотеку, обязан прятать её и в своей сигнатуре: иначе
   «граница» существует только в `build.gradle.kts`. `wbparser` говорит
   `BrowserPage`, а не Playwright's `Page`; `:browser` — `implementation`, а не
   `api` (ADR `2026-10-22-the-browser-stack-is-a-library`). Механическая часть
   правила проверяется: Playwright не должен появляться в `wbparser` и `app`
   (`scripts/ci/check-repo-rules.py`) — граница проверяется с обеих сторон, иначе
   она проверяется только наполовину.

6. **Сторон-эффект подключается только через `SideInterpreterRegistry`.** Каждый
   вариант `Side` **MUST** иметь интерпретатор в каждом `runTarget`. Реестр тотален
   по построению: интерпретаторы non-null, `when` исчерпывающий, поэтому
   «забытый» интерпретатор — ошибка компиляции, а не рантайм-сюрприз (ADR
   `2026-10-20-the-registry-is-total-by-construction`).

7. **Домен не знает о базе.** Метаданные схемы и запросы к ним живут в
   `infra/db/`, а не в `domain/`: домен — это набор Kotlin-типов, которые ничего
   не знают о хранилище. Проверяет `scripts/ci/check-domain-purity.sh`.

## Тесты

8. **Критичный вход приезжает с тестом на путь отказа.** У публичного входа
   компонента, который отдаёт ресурсы наружу (`BrowserPool.borrowPage`,
   `BrowserReconciler.reconcile`, `AdsPowerApi.*`), **MUST** быть тест, где он
   бросает. Покрытие строк этого не видит: успешный путь закрыт, путь отказа — нет,
   и пол остаётся зелёным.

9. **Тестовые двойники — `Fake*`, а не моки.** Мокки допустимы там, где нужно
   проверить *взаимодействие* с библиотекой; для собственных классов — `Fake*`,
   который отвечает и запоминает. Мок, который отвечает `relaxed = true` на всё,
   проверяет не контракт, а своё собственное существование. Имя проверяется
   машиной: двойник нашего типа, названный `Mock*`, — это finding
   (`scripts/ci/check-repo-rules.py`). Чужие `Mock*` (Spring-овские
   `MockHttpServletRequest`) — не наш двойник, и правило про них молчит.

10. **Тест, который не может упасть, — не тест.** Признак: он проходит и когда
    код сломан. Хороший признак теста на путь отказа — он падает, когда
    освобождение ресурса убрать.

## Жизненный цикл

11. **`exitProcess()` — только там, где веб-сервера нет.** `SpringApplication.run()`
    для веб-сервера возвращается почти сразу, и `exitProcess` убивал JVM через
    ~70 мс после «Started». В серверном режиме `main()` просто возвращается:
    Tomcat держит процесс на non-daemon-потоках.

12. **Ресурс, который грузится в рантайме, объявляется в рантайме.** `compileOnly`
    означает «нет в рантайм-класспате». `exposed-java-time` был объявлен так, при
    этом `tests/` добавлял его обратно как test-зависимость: все тесты зелёные, а
    прод падает на первом же запросе к таблице. Тип колонки в схеме — не
    compile-time метаданные, его вызывают при каждом чтении и записи. **Always**
    проверять рантайм-класспат сборкой `bootJar`, а не только тестами.

13. **Exclude-лист DAGP может только уменьшаться по существу.** Запись,
    описывающая упаковку зависимости (starter — pom без классов; агрегатор —
    неразделимая на части), неустранима никаким изменением в этом репозитории и
    остаётся; запись, скрывающая находку, которую закрыла бы строка кода,
    запрещена. Новая запись — только с причиной в ADR. Запись удаляется в том же
    коммите, что чинит находку.

## Что проверяет машина

Эти правила не дублируются здесь: сборка проверяет их сама, и нарушение видно
автору кода до ревью.

| Правило | Кто проверяет |
|---|---|
| Нет `!!` в prod-коде | `scripts/ci/check-repo-rules.py` |
| Нет `delay(-1L)` как sentinel | там же |
| Нет Spring вне `app/` | там же |
| `:browser` не знает ни о базе, ни о фреймворке, ни о HTTP-клиенте | там же |
| Playwright не назван вне `:browser` | там же |
| Двойник нашего типа назван `Fake*`, а не `Mock*` | там же |
| Нет `CHANGELOG.md` | там же |
| Нет `fixDependencies` в CI | там же |
| Нет запинненного `org.gradle.java.home` | там же |
| `compileOnly` не течёт в рантайм | `scripts/ci/check-compileonly-runtime.sh` |
| Тип в публичной сигнатуре объявлен в `api` | DAGP (`./gradlew buildHealth`) |
| Домен без инфраструктурных импортов | `scripts/ci/check-domain-purity.sh` |
| Baseline detekt не растёт | `scripts/check-baseline-ratchet.py` |
| Отчёт покрытия не отстаёт от своих частей | `scripts/check-coverage.py` |
