---
title: "Покрытие меряется по коду, а не по модулю, которому он принадлежит"
date: 2026-10-20
tags: [build, tests, gate, coverage]
---

## Context

Гейт покрытия читал **отчёт каждого модуля**: строка `app` измерялась по
`app/build/reports/kover/report.xml`, строка `wbparser` — по своему.

Отчёт модуля содержит только классы этого модуля и только покрытие, которое дали его
**собственные** сьюты. Тесты приложения живут в модуле `tests` — по решению из ADR
`2026-10-20-coverage-is-measured-where-the-code-lives` (модуль `tests` отошёл к тому,
что действительно нуждается в миграциях Flyway). Итог: **35 классов `app` отчёт модуля
показывал как непокрытые (0 %)**, а merged-отчёт по тем же классам — как 57–100 %.

| класс | отчёт `app` | merged-отчёт |
|---|---|---|
| `CatalogQueries` | 0 % | 97.3 % |
| `CatalogRoutes` | 0 % | 99.4 % |
| `WebSecurityConfig` | 0 % | 97.0 % |
| `DemoSeedRunner` | 0 % | 96.1 % |

Floor `app` стоял на 31 % при измерении 32.1 %. То есть гейт охранял число, которое
описывало не покрытие приложения, а покрытие приложения **собственными** сьютми — а у
приложения их почти не было, потому что его тесты живут в другом модуле.

Настоящий пробел в покрытии при этом был виден в merged-отчёте, и именно он гонял
работу: `RealAdsPowerApi` 6 %, `BrowserDownloader` 14 %, `CdpAutomation` 21 %.

## Idea

1. **Перенести тесты `app` в модуль `app`.** Отвергнуто: те, кому нужны миграции
   Flyway, должны жить в модуле `tests` — это и есть его назначение по ADR. Перенос
   означал бы либо дублирование фикстуры, либо новый модуль ради фикстуры, и решал бы
   не ту задачу: чинить надо было измерение, а не раскладку тестов.
2. **Оставить всё как есть, но честно назвать строки floors.** Отвергнуто: строка,
   которая называется `app` и при этом не про `app`, вводит в заблуждение того, кто её
   читает, — и это тот же класс дефекта, что и гейт, который нельзя провалить.
3. **Мерять каждую строку по merged-отчёту с фильтром по пакетам.** Выбрано.

## Decision

**Каждая строка floors измеряется на общем (merged) отчёте, по пакетам этой строки.**

- `app` — пакеты `ru/wbparser/app/**`
- `wbparser` — `ru/wbparser/**`, кроме `ru/wbparser/app/**`
- `merged` — всё

`scripts/check-coverage.py` получил реестр `MODULE_PACKAGES` / `MODULE_EXCLUDED` и
функцию `module_coverage(module)`; `scripts/raise-kover-floor.py` меряет тем же —
иначе ратчет двигал бы пол к тому, чего гейт не проверяет.

**Floors подняты: `app` 31 → 84, `wbparser` 77 → 80.** Измерения: 85.2 % и 81.5 %
(merged — 82.8 %, пол остался 81 %).

## Rationale

Пол должен измерять код, а не модуль, которому код принадлежит. Класс, покрытый на
97 %, не должен числиться непокрытым из-за того, что его тест лежит в соседнем
модуле.

Побочный, но главный эффект: строка floors перестала быть «средней температурой по
репозиторию» и стала тем, чем её читают — «сколько покрыто **этого** модуля». При
этом локализация не потерялась: фильтр по пакетам даёт и merged-отчёт, и отчёт
модуля; изменился источник измерения, а не детальность.

Ещё один эффект: `app` с floor 84 % теперь ловит новый код приложения без теста
сразу. При 31 % он не ловил ничего.

## Consequences

- **Always** мерить строку floors по merged-отчёту с фильтром по пакетам модуля.
  Отчёт модуля не видит покрытие, которое дали чужие сьюты.
- **Never** читать из отчёта модуля вывод о покрытии приложения: в этом репозитории
  его тесты живут в модуле `tests`, и 35 классов выглядели непокрытыми, будучи
  покрытыми на 57–100 %.
- **Always** держать гейт покрытия и ратчет полов на одном измерении: ратчет, который
  меряет иначе, двигает пол к тому, чего гейт не проверяет.
- **Never** выводить «покрытие модуля» из отчёта, который этот модуль не видел.
