## Context

Краул не может прочитать ни одной страницы Wildberries без настоящего браузера.
Браузер — это AdsPower: виртуальный дисплей, CLI AdsPower и Chrome, который он
запускает. Локальный API AdsPower живёт на loopback, а CDP-эндпоинт запущенного
Chrome — тоже на loopback того же хоста.

На VPS браузера не было вообще: ни контейнера, ни systemd-юнита. При этом два
контракта деплоя не совпадали — этот репозиторий везёт образ и запускает его
compose'ом, а роль `wbparser` в Caddy-vps клонировала репозиторий, собирала JAR
на хосте (у хоста нет исходящей сети для Gradle) и запускала её systemd'ом.

Топология «оба на host-сети» решает доступность (Local API и CDP доступны по
127.0.0.1), но при этом приложение слушает 0.0.0.0:8080 на публичном адресе
VPS, а вместе с ним — админский API. Compose-файл это прямо запрещал и правильно.

## Idea

1. **Один образ**: положить браузер в образ краула. Дёшево, но браузер — не
   приложение: он меняется (новое ядро Chrome, новая версия CLI), и каждое такое
   изменение пересобирало бы приложение.
2. **Два образа на host-сети**: доступно, но админский API оказывается на
   публичном интерфейсе.
3. **Два образа, общая сетевая namespace**: браузер работает в той же сетевой
   namespace, что и краул, поэтому Local API и CDP-порты доступны по 127.0.0.1 —
   и при этом ничего не публикуется наружу.

## Decision

**Репозиторий собирает и публикует два образа; Caddy-vps тянет их по digest и
поднимает оба.**

| образ | что это | тег |
|---|---|---|
| `ghcr.io/gazon1/wb-parser` | краул | короткий SHA коммита |
| `ghcr.io/gazon1/wb-parser-adspower` | рантайм браузера (Xvfb + CLI AdsPower) | тот же SHA |

**Браузер делит сетевую namespace краула** (`network_mode: "service:wb-parser"`).
Отсюда следует всё остальное:

- Local API AdsPower доступен краулу по `127.0.0.1:50325` — и больше нигде;
- CDP-порт Chrome, который выдаёт API, доступен по тому же 127.0.0.1, без
  переписывания URL;
- наружу не выставлен ни один порт: namespace краула — это мост caddy_net, а не
  публичный интерфейс;
- Caddy и витрина достают краул по имени контейнера, как и раньше.

**Состояние AdsPower — именованный том**, общий для обоих контейнеров: ядро
Chrome (520 МБ) качается рантаймом один раз и переживает передеплой, а
pre-flight краула видит профили, которые материализовал рантайм. Ядро не
запекается в образ: его умеет скачать только запущенный рантайм, а тому нужен
ключ AdsPower — и ключ в слое образа это утечка.

**Ключ AdsPower едет в отдельном `browser.env`**, который compose передаёт
буквально (через `env_file`), а не интерполирует: пароль с `$` не должен
разворачиваться. У краула свои credentials в `app.env`, у браузера — свои; ни
одна из сторон не видит чужого секрета.

**Flyway включается обратно.** База на 91.188.212.209 переведена на схему
приложения (v6), её история миграций совпадает с миграциями репозитория, и
новая миграция теперь применяется деплоем, а не руками.

## Rationale

Digest вместо тега: тег можно переставить, digest называет одни и те же байты.
Витрина, которая читает каталог краула, сверяется с теми же байтами, что и
развёрнутый контейнер, — и откат возвращает предыдущий digest, а не «что там
сейчас по этому тегу».

Общая namespace вместо host-сети: единственный способ получить и loopback-
доступность, и отсутствие публикации наружу. Всё остальное требует либо
публикации портов, либо переписывания адресов в коде.

Два образа вместо одного: браузер и приложение живут разными сроками и
меняются по разным поводам.

## Consequences

- **Always** публиковать оба образа из одного коммита и поднимать их одним
  compose-вызовом: браузер без краула и краул без браузера не работают.
- **Never** отдавать контейнеру краула host-сеть: Local API AdsPower и админский
  API окажутся на публичном адресе.
- **Always** держать ключ AdsPower в файле, который compose передаёт буквально.
- **Never** запекать ядро Chrome в образ: ключ AdsPower попадёт в слой.
- **Always** давать гейту здоровья время на первый старт: ядро Chrome (520 МБ)
  качается при первом запуске, поэтому таймаут гейта — 600 с, а не 180.
- **Never** включать Flyway обратно, пока история миграций базы не совпадает с
  миграциями сборки: Flyway падает на проверке контрольной суммы, и падает на
  каждом деплое.
- **Always** читать compose-файл из репозитория приложения: как краул работает —
  это его контракт, и его изменение проходит ревью здесь, а не в шаблоне роли.
