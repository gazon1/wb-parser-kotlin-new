---
title: "Пагинация не увеличивает глубину краула"
date: 2026-10-20
tags: [pipeline, domain]
---

## Context

`Pipeline` добавлял задачу следующей страницы с `depth = done.task.depth + 1`: страница
казалась «уровнем глубже» в дереве категорий.

С внутренним API каталога это неверно, и ошибка была тихой:

- `max_depth = 2` обрезал краул на второй странице каждого каталога;
- прогон отчитывался «132 страницы, 13 200 товаров» — по одной странице на цель, то есть
  ровно то, что и ожидалось;
- лимит страниц (`known_pages_limit` / `max_pages_per_catalog`) не срабатывал никогда, его
  достичь было невозможно.

## Idea

- Оставить `depth + 1` и поднять `max_depth` до числа страниц. Тогда `max_depth` перестаёт
  быть «глубиной по дереву» и становится вторым именем лимита страниц — два лимита на
  одно ограничение.
- Развести глубину по дереву и глубину пагинации отдельными счётчиками. Точнее, но это
  второй параметр в модели задачи и вторая ось в dedup-отпечатке.
- Не считать страницу уровнем дерева: глубина — это «насколько глубоко краул спустился по
  дереву категорий», а пагинация — это «следующая страница того же каталога».

## Decision

Задача следующей страницы наследует глубину родителя: `depth = done.task.depth`.

`stopAt(pages, depth)` вызывается с той же глубиной, что и у текущей задачи.

## Rationale

Глубина отвечает на вопрос «как далеко краул ушёл от корня дерева категорий». Внутренний
API отдаёт один каталог за запрос и в дерево не спускается: страницы одного каталога — это
одна категория, а не её уровни.

Третий вариант (раздельные счётчики) честнее семантически, но платит вторым измерением в
модели задачи, в отпечатке для дедупликации и в проверке лимитов — ради того, чего
внутренний API не делает.

Дедупликация по `(url, depth)` при этом работает даже лучше: страница, ссылающаяся сама на
себя, отбрасывается по отпечатку сразу, а не на следующем витке.

## Consequences

- **Always** считать `max_depth` глубиной по дереву категорий, а не лимитом страниц.
- **Never** использовать `max_depth` для ограничения числа страниц каталога: лимит
  страниц — это `known_pages_limit` (у цели) и `max_pages_per_catalog` (у раннера).
- Проверка `stopAt` на границе пагинации теперь вызывается с глубиной текущей задачи.
- Тест `PipelineDedupTest` на самоссылку ждёт одну страницу вместо трёх: очередь
  опустела, а не упёрлась в лимит.
